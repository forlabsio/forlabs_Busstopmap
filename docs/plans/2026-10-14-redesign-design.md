# 마라톤 노선 관리 리뉴얼 설계

작성일 2026-10-14 · 대상 저장소 `forlabs-busstopmap`

## 왜 고치는가

현재 앱은 동작하지만 세 가지가 걸린다.

1. **노선 작성 비용** — 190개 정류장짜리 풀코스를 만들려면 마커를 190번 클릭해야 한다.
2. **성능** — 지역을 고르면 DOM 마커를 전부 그린다. 서울만 16,980개다.
3. **외형** — Tailwind CDN 기본 버튼과 고정 사이드바. 지도는 OSM 래스터 타일.

## 결정 사항

| 항목 | 결정 |
|---|---|
| 범위 | 지도 엔진까지 교체하는 풀 리뉴얼 |
| 지도 | MapLibre GL + CARTO 벡터 타일(positron / dark-matter), 라벨은 `name:ko` |
| 디자인 | Toss 디자인 시스템 (oh-my-design.kr 토큰) |
| 노선 작성 | 거점을 찍으면 사이 구간의 정류장을 자동 선택 |
| 데이터 | 전국 64,347개를 한 번에 로드하고 클러스터링 |
| 추가 | 다크모드, 모바일 대응 |
| 공유 | 보기 전용. 노선을 링크에 담아 전달 (서버/DB/로그인 없음) |
| 배포 | 정적 호스팅 (모바일에서 열기 위함) |
| 제외 | GPX 내보내기, 공동 편집, 계정 |

## 구조

```
index.html          앱 셸 (~60KB)
data/stops.json     전국 정류장 압축 배열 [[id,name,lat,lng,city], ...]
build.py            CSV → stops.json 변환 + 배포용 단일 HTML 생성
filtered_bus_stops.csv   원본 (유지)
```

데이터를 외부 파일로 빼면 `file://` 더블클릭 실행이 막힌다(fetch 차단). 상시 사용은 지금처럼
로컬 서버로 하고, 팀원에게 파일 하나로 건넬 때는 `build.py --single`로 데이터가 인라인된
배포용 HTML을 뽑는다. 두 경로를 모두 유지한다.

`stops.json`은 필드명을 뺀 배열 형태라 JSON.parse가 빠르다(64,347행 기준 0.3초 이내 목표).
파싱은 Web Worker에서 돌려 첫 화면을 막지 않는다.

## 지도와 마커

- 정류장은 GeoJSON source 하나 + `cluster: true`. 줌 13 미만은 클러스터(개수 뱃지),
  줌 13 이상은 개별 점. DOM 마커는 쓰지 않는다.
- 노선은 casing(흰 테두리) + line + 정점 circle 3개 레이어. 출발/골인만 HTML 마커.
- 지역은 선택 게이트가 아니라 **필터 칩**으로 격하한다. 서울→경기를 넘나드는 코스를 만들 수 있다.

## 노선 작성

1. **거점 찍기** — 지도를 클릭해 거점을 순서대로 추가한다(최소 2개).
2. **자동 채우기** — 거점을 이은 경로선에서 **160m 이내** 정류장을 뽑고, **간격 슬라이더**
   (기본 250m, 100m~1km)로 솎아낸다. 알고리즘은 이미 검증됐다(상암→여의도 코스 24개 추출).
3. **미리보기** — 확정 전 회색으로 보여준다. 확정하면 노선에 들어간다.
4. **손보기** — ✕로 빼고, 지도 클릭으로 더하고, 패널에서 드래그로 순서를 바꾼다.
5. **거리** — 구간 거리와 누적 거리를 항상 표시한다(Haversine, 직선 기준).

직선 거리이므로 실제 주행 거리보다 짧게 나온다. 패널에 그 사실을 적는다.

## 화면

- 전체화면 지도 위에 떠 있는 요소들: 상단 검색바(⌘K) + 필터 칩, 우측 노선 패널,
  하단 툴바(거점 찍기 / 순서 바꾸기 / 인쇄 / 테마).
- 모바일은 노선 패널을 바텀시트로 전환한다(3단계: 손잡이만 / 절반 / 전체).
- 다크모드는 CSS 변수 교체 + dark-matter 타일. 시스템 설정을 따르고 수동 토글도 둔다.

## 호환성

저장 포맷을 바꾸지 않는다.

```json
{ "routes": [ { "id", "name", "region", "stops": [ { "id", "name", "lat", "lng" } ], "createdAt" } ] }
```

`localStorage['marathon-routes']` 키와 스키마를 그대로 쓴다. 지금 저장된 2개 노선
(29개 / 190개)이 새 앱에서 그대로 열려야 한다. 이것이 1순위 수용 조건이다.
파일 내보내기/불러오기는 현재 구현을 그대로 가져간다.

`region` 필드는 더 이상 로딩 게이트가 아니지만, 기존 데이터를 깨지 않기 위해 계속 기록한다.

## 공유와 배포

작업자는 **보기만** 한다. 편집은 소유자 브라우저에서만 일어난다. 그래서 DB도 로그인도 두지 않는다.

### 공유 링크

노선을 URL에 담는다. 정류장 ID만 넣고 deflate + base64url로 압축한다. 실측값이다.

| 노선 | 정류장 | 링크 길이 |
|---|---:|---:|
| 상암→여의도 | 29 | 약 196자 |
| 풀코스 | 190 | 약 726자 |

카카오톡·문자로 보내도 안전한 길이다(2,000자 이하). 이름과 좌표까지 넣으면 풀코스가
3,736자가 되어 메신저에서 잘릴 수 있으므로, ID만 넣고 뷰어가 데이터셋에서 이름을 찾는다.

```
https://<도메인>/?r=eJxlkMtuwzAMBH-F...
```

`?r=`이 있으면 **뷰어 모드**로 뜬다. 노선과 거리, 정류장 목록만 보이고 편집 UI는 감춘다.
"내 노선으로 복사" 버튼으로 자기 브라우저에 가져갈 수 있다.

### 고정 링크 (선택)

대회 코스처럼 주소가 바뀌면 안 되는 경우를 위해 `published/<슬러그>.json`을 읽는 경로를
같이 넣는다. 파일을 커밋하면 `/?w=mapo-2026`으로 항상 같은 주소에서 열린다. 발행은 커밋으로만
가능하므로 작업자가 내용을 바꿀 수 없다.

### 배포

정적 호스팅에 올린다. 빌드 산출물은 `index.html` + `data/stops.json` + 에셋뿐이다.
`stops.json` 3.5MB는 brotli로 약 1MB가 되어 모바일에서 1~2초면 받는다.
뷰어 모드는 노선만 그리면 되므로 데이터셋 로딩을 뒤로 미루고 선부터 그린다.

## 인쇄

dom-to-image를 걷어내고 `map.getCanvas().toDataURL()`로 바꾼다. MapLibre 맵 생성 시
`preserveDrawingBuffer: true`가 필요하다. 지도 이미지 + 정류장 목록 + 총거리를 A4로 뽑는다.

## 검증

구현 중 다음을 매번 확인한다.

1. 기존 노선 2개를 불러와 정류장 수와 폴리라인이 일치하는가 (29 / 190).
2. 내보내기 → 빈 프로필에서 불러오기 → 동일한가.
3. 전국 64,347개 로드 후 첫 화면까지 2초 이내인가.
4. 거점 자동 채우기가 상암→여의도 코스를 20~30개 정류장으로 재현하는가.
5. 라이트/다크, 데스크톱/모바일 폭에서 스크린샷 확인.
6. 공유 링크를 만들어 다른 브라우저에서 열었을 때 같은 코스가 뜨는가.
7. 배포본을 실제 휴대폰 화면 크기에서 열어 첫 화면까지 걸리는 시간.
